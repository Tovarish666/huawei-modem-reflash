# huawei-modem-reflash

Автоматическая перепрошивка USB-модемов Huawei на чипсете Balong из Linux по схеме «Игла 2.0»:
запустил скрипт → вставил модем → в терминале **ГОТОВО** или **ОШИБКА** с причиной.

Писалось для модемов, которые от износа NAND начали «борогозить» (теряют сеть, забывают адрес),
и для современных ноутбуков, где Windows не видит аварийный COM-порт модема. Linux работает с ним без драйверов.

| Модель | Плата | Статус |
|---|---|---|
| E3372h-153 | CL2E3372HM | ✅ `e3372h/reflash.sh` |
| E3372s-153 | CL1E3372SM | ⏳ планируется |
| Vodafone K5160 | — | ⏳ планируется |

> ⚠️ Скрипт для E3372h **отказывается работать с другими моделями**: у E3372s другая платформа (V7R2 вместо V7R11),
> и загрузчик с таблицей разделов от E3372h превратят её в кирпич.

## Установка

Нужен хост с Debian 12/13 или Proxmox VE 8/9, root и порт USB 2.0.

```bash
git clone https://github.com/Tovarish666/huawei-modem-reflash.git
cd huawei-modem-reflash
./setup.sh
```

`setup.sh` ставит пакеты (`fastboot`, `adb`, `usb-modeswitch`, сборочные), собирает утилиты
[forth32](https://github.com/forth32) в `tools/` и скачивает прошивки из
[релиза](https://github.com/Tovarish666/huawei-modem-reflash/releases) со сверкой SHA-256.

## Использование

```bash
e3372h/reflash.sh            # прошить; модем можно вставить до или после запуска
e3372h/reflash.sh --check    # только проверить файлы и показать, в каком режиме модем
```

| Ключ | Что делает |
|---|---|
| `--via FILE` | переходная прошивка (по умолчанию `…M_AT_05.10_nv.exe`); `--via none` — без неё |
| `--go N` | сколько раз выполнить GO (по умолчанию 3) |
| `--keep-bbt` | GO без сброса таблицы бэдблоков (ответ «1» в `Это GO.cmd`) |
| `--force-1443` | модем вставлен сразу в аварийном режиме (иглой) — модель не проверить |
| последний аргумент | итоговая прошивка (по умолчанию `…WEBUI_17.100.12.06.03_HILINK.exe`) |

Логи пишутся в `logs/`, резервные копии NV — в `backups/<IMEI>-<дата>/`. Обе папки в git не попадают.

## Что происходит

```
аварийка → балон → аварийка → GO ×3 → балон → переходная прошивка → итоговая прошивка → HiLink → проверка
```

1. **Проверка модели** — по веб-API (`HardwareVersion`), `AT^VERSION?` или `AT^DLOADINFO?`. Не E3372h-153 — отказ.
2. **Аварийный режим без иглы.** Если в прошивке есть ADB (есть у прошивки dinis.ru), скрипт снимает резервную копию
   загрузчика и NV, затирает загрузчик (`m3boot`, `fastboot`) и перезагружает модем — BootROM, не найдя загрузчик,
   сам поднимает аварийный порт. Если загрузчик уже повреждён, модем приходит в аварийку сам; иначе — игла.
3. **Балон** — `usblsafe` в память и стирание загрузчика, чтобы дальше модем сам возвращался в аварийку.
4. **GO** — как `Это GO.cmd` с ответом «2»: `usblsafe -b` и `fastboot erase` всех разделов,
   кроме `nvbacklte` и `nvdefault` (в них IMEI и калибровка, из них модем восстанавливает NV).
5. **Балон в режиме прошивки → переходная → итоговая прошивка** через `balong_flash`.
6. Если модем ушёл в режим обновления загрузчика (`1442`, `dload type:1`) — прошивка повторяется там.
   Из режима первой загрузки (`1442`, `dload type:0`) выводит `AT^RESET`.
7. **HiLink** — адрес модема берётся по DHCP (бывает не `192.168.8.1`), затем сверка версии и IMEI через веб-API.

Если ADB нет (прошивка без него или HiLink встал криво), скрипт идёт через режим обновления
(`AT^GODLOAD`) — **без балона и GO** — и прямо об этом пишет.

### Режимы модема на USB

| ID | Режим |
|---|---|
| `12d1:1443` | аварийка (BootROM), один порт `USB COM` |
| `12d1:36dd` | fastboot загрузчика `usblsafe` |
| `12d1:1c05` | режим прошивки `usblsafe`, порт прошивки — интерфейс 2 |
| `12d1:1442` | AT-порт + накопитель: режим обновления или первая загрузка после прошивки |
| `12d1:155e` | отладочный режим (AT-порты + NCM) |
| `12d1:1f01` | стартовый режим (накопитель) |
| `12d1:14dc` | HiLink |

## Подводные камни

- **«Сетевой кабель не подключён»** в Windows / нет линка в Linux — прошивка встала криво. Вставьте модем заново
  и запустите скрипт ещё раз; если и ADB нет — через иглу.
- На время работы скрипт отключает автопереключение `usb_modeswitch` (иначе модем уходит в HiLink раньше,
  чем скрипт успеет прочитать AT-порт) и возвращает его при выходе.
- Хабы USB часто заявляют поштучное управление питанием, но реально его не снимают — программно «передёрнуть»
  модем нельзя, иногда нужно вынуть его руками.
- Чтение `nvimg` через ADB на части прошивок зависает и роняет ADB, поэтому в резервную копию он не входит
  (это рабочая копия NV, модем восстанавливает её из `nvbacklte`).
- `-b` сбрасывает таблицу бэдблоков. Если память изношена по-настоящему, сбойные блоки со временем вернутся.

## Файлы

- `e3372h/firmware/` — прошивки скачиваются из релиза:
  `E3372h-153_Update_22.333.01.00.00_M_AT_05.10_nv.exe` (переходная, из пакета «Игла 2.0»),
  `E3372h-153_Update_22.333.01.00.00_WEBUI_17.100.12.06.03_HILINK.exe` (итоговая, с [dinis.ru](https://dinis.ru)).
- `e3372h/ptable-hilink.bin` — таблица разделов из пакета «Игла 2.0».
- `lib/at.py` — отправка AT-команд, `lib/dhcp-probe.py` — узнать адрес модема по DHCP, не меняя маршрутов.
